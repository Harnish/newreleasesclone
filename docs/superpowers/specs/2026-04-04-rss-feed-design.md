# Design: Per-User RSS Feed

**Date:** 2026-04-04  
**Status:** Approved

## Summary

Expose an unauthenticated Atom feed at `GET /feed/<token>` that returns a user's tracked releases sorted newest-first. Each user gets a UUID-like token stored in the database; the token is opaque and non-guessable but not treated as a revocable secret. The feed URL is shown in the account settings panel.

## Goals

- Unauthenticated Atom 1.0 feed per user
- Token in path (not query string) for feed-reader compatibility
- Token generated at user registration, stored persistently
- Feed URL shown in the existing account settings panel (⚙ → username)

## Non-Goals

- Token revocation / regeneration
- Backfilling tokens for existing users (existing users simply have no feed URL — the UI hides the section)
- Per-project feeds
- RSS 2.0 (Atom 1.0 is sufficient and simpler to produce correctly)
- Pagination

## Schema Changes

Schema bumps from v7 to v8 on the master branch. If another v8 migration is merged first (e.g., `feat/immediate-email`), renumber this migration to v9.

```sql
ALTER TABLE users ADD COLUMN rss_token TEXT;
CREATE UNIQUE INDEX IF NOT EXISTS idx_users_rss_token ON users(rss_token) WHERE rss_token IS NOT NULL;
```

Token is `NULL` for users created before this migration. New users get a token at registration. The unique index enforces no two users share a token.

## Token Format

16 random bytes from `crypto/rand`, encoded as a lowercase 32-character hex string. Example: `a3f7c2e1b4d09285e6f3a1c7d0b28495`. Generated by a package-level `newRSSToken() string` helper in `store.go`.

## Model Changes (`models.go`)

Add `RSSToken string` to the `User` struct:

```go
type User struct {
    ID            string `json:"id"`
    Username      string `json:"username"`
    Email         string `json:"email"`
    EmailVerified bool   `json:"email_verified"`
    RSSToken      string `json:"rss_token"`
}
```

## Store Changes (`store.go`)

### `newRSSToken() string`

Package-level helper, unexported:

```go
func newRSSToken() string {
    b := make([]byte, 16)
    if _, err := rand.Read(b); err != nil {
        panic(fmt.Sprintf("crypto/rand failed: %v", err))
    }
    return hex.EncodeToString(b)
}
```

Uses `crypto/rand` and `encoding/hex`.

### `CreateUser` update

Generate and store the RSS token when creating a new user. The `INSERT INTO users` statement adds `rss_token` to the inserted columns.

### `GetUserByID` update

Add `rss_token` to the SELECT and scan it into `u.RSSToken`.

### `GetUserByRSSToken(token string) (*User, error)`

```sql
SELECT id, username, email, email_verified FROM users WHERE rss_token = ?
```

Returns `(nil, nil)` if no user matches (not an error — feed handler returns 404).

### `GetUserReleasesForFeed(userID string, limit int) []Release`

Same query as `GetUserReleases` with `LIMIT ?` appended:

```sql
SELECT r.id, r.repo_id, r.name, r.version, r.platform, r.url,
       r.published_at, r.description, r.release_notes
FROM releases r
INNER JOIN user_repos ur ON ur.repo_id = r.repo_id
WHERE ur.user_id = ?
ORDER BY r.published_at DESC
LIMIT ?
```

Called from the feed handler with `limit = 50`.

## API Changes (`handlers.go`)

### `GET /api/me` — add `rss_token`

`handleMe` already returns `*User` embedded in the response. Since `RSSToken` is now a field on `User` (populated by `GetUserByID`), it is included automatically. No other change needed — existing users have an empty string, which the UI treats as "no feed".

### `GET /feed/{token}` — new unauthenticated handler

Registered in `main.go` without `requireAuth`:

```go
http.HandleFunc("/feed/", handleFeed)
```

Handler extracts the token from the path (`strings.TrimPrefix(r.URL.Path, "/feed/")`), looks up the user via `store.GetUserByRSSToken(token)`. Returns 404 if not found.

Fetches `store.GetUserReleasesForFeed(user.ID, 50)`, builds Atom XML, returns with `Content-Type: application/atom+xml; charset=utf-8`.

**Base URL construction:** derived from the request — `scheme + "://" + r.Host` where scheme is `"https"` if `r.TLS != nil` else `"http"`.

## Feed Format (`handlers.go`)

Plain Atom 1.0, hand-built with `encoding/xml`. No external dependency.

```xml
<?xml version="1.0" encoding="utf-8"?>
<feed xmlns="http://www.w3.org/2005/Atom">
  <title>username's releases</title>
  <link href="https://example.com/feed/token" rel="self"/>
  <updated>2026-04-04T10:00:00Z</updated>
  <id>https://example.com/feed/token</id>
  <entry>
    <title>myproject v1.2.3</title>
    <link href="https://github.com/x/myproject/releases/tag/v1.2.3"/>
    <id>https://github.com/x/myproject/releases/tag/v1.2.3</id>
    <updated>2026-04-03T18:00:00Z</updated>
    <summary>release notes here (omitted if empty)</summary>
  </entry>
  ...
</feed>
```

- Feed `<updated>`: most recent `published_at` in the list, or current time if list is empty.
- Entry `<id>`: the release URL (stable, unique per release).
- Entry `<summary>`: release notes if non-empty; element omitted otherwise.
- All string values XML-escaped via `encoding/xml` marshalling.

## Route Registration (`main.go`)

```go
http.HandleFunc("/feed/", handleFeed)
```

Added alongside other unauthenticated routes (verify-email, etc.). No `requireAuth` wrapper.

## Frontend Changes (`ui.go`)

In the account settings panel (`renderAccountPanel` / the DOM-building code for the ⚙ panel), after loading `/api/me`, display the feed URL as a read-only text input with a "Copy" button:

```
RSS Feed
[https://example.com/feed/a3f7c2e1...]  [Copy]
```

- Section title: "RSS Feed"
- Input: `readonly`, full URL `baseURL + "/feed/" + currentUser.rss_token`
- Button: copies to clipboard via `navigator.clipboard.writeText(...)`, shows brief "Copied!" label
- The section is shown only when `currentUser.rss_token` is non-empty
- `baseURL` is `window.location.origin`

The account settings panel is built via DOM API (same pattern as the email toggle in the project settings panel), so no `innerHTML` concerns for new additions.

## Error Handling

- `GetUserByID` DB error (including missing `rss_token`): `handleMe` already returns 500 on user-not-found; `rss_token` being empty string means UI hides the RSS section silently
- `GetUserByRSSToken` no match: 404 (no body needed — feed readers handle this)
- `GetUserReleasesForFeed` error: return empty feed (valid Atom with no entries) rather than 500
- Empty release list: valid Atom feed with no entries, `<updated>` = current time

## Testing

- Store: `CreateUser` generates token; `GetUserByID` returns it in `RSSToken` field
- Store: `GetUserByRSSToken` (found, not found)
- Handler: `GET /feed/<token>` returns 200 with `application/atom+xml` content-type and valid XML
- Handler: `GET /feed/<unknown>` returns 404
- Handler: `GET /api/me` includes `rss_token` field
- Feed XML: entry titles, links, and updated timestamps are correct; empty release list produces valid feed
